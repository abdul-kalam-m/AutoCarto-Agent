## 2. Left column — replace "Why constrain the LLM?" (~200 words → ~95)

**Header:**

> ## LLMs draw beautiful, wrong maps

**Failure gallery (three bullets, each one failure + its gate):**

> - **Classification.** Equal-interval breaks on a skewed variable collapse **414 of 530 tracts (78%) into one class** — the map renders fine and says nothing. *→ Gate 2*
> - **Encoding.** Bivariate palettes get applied to variable pairs with **no spatial cross-correlation** — a map of pure noise that looks like a pattern. *→ Gate 3b*
> - **No guarantees.** Temperature 0 is not determinism, and self-critique is another stochastic pass. Prompting cannot *enforce* anything.

**Thesis paragraph:**

> **AutoCarto-Agent removes the LLM's statistical authority instead of improving its judgment.** The LLM parses intent, selects visual variables and templates, and assembles code. A deterministic engine computes every number, vetoes invalid proposals, and — the key move — **rejects with a prescription**: the mandated method, the precomputed break values, splice-ready code. Rejection with prescription converges in ≤3 iterations, because the LLM's remaining job is transcription of the mandated method. Every decision lands in a machine-readable trace.

*Rationale:* the 78% figure is the poster's own F-NEW-1 headline number (computed, tested); leading the gallery with it links the text column to the killer visual. Each bullet names the gate that catches it — the architecture becomes the answer to the failure list. The old column's ~200-word paragraph buried this structure (Guide §4.2-7).

**Removed from the old poster — do not reintroduce:** `GVF … 0.894` (untraceable; wrong), `23% of proposals rejected` (unfalsifiable as printed, appeared in *two* places — the Gate 2 badge §3a-ii **and** a banner baked into `architecture_boundary.png` itself, §3a-i), `100% sandbox escape prevention` (overclaim baked into the same banner), `Reflection: Blocked` under gVisor (misattributed).

**⚠ Timing claim — read before the live demo, not just before printing.** "Core validation < 3 s" refers to the number `autocarto demo` **prints internally** (`Total wall-clock: ... ms` in the log/stdout — observed 0.8–2.7 s across many runs). It is **not** the total time from typing the command to seeing output: that includes one-time Python/NumPy/SciPy/Matplotlib interpreter startup, measured at **3.5–6 s** on the dev laptop during this verification pass — an ordinary cost of any Python CLI using this stack, not a property of the validation pipeline. **Never say "the command finishes in under 3 seconds" out loud or in print** — say "the validation itself — what you see printed here — is under 3 seconds," and let the visible internal timer line do the proving. This distinction was not enforced in earlier drafts of this poster copy or in the Presentation Guide; both are corrected as of this pass (2026-07-26).

**⚠ Trace-identity claim — the same "read closely before a live check" caution applies here.** `autocarto demo` writes **four** trace files. Re-verified 2026-07-26 (two fresh runs, `diff` on each file): `gate2_classification_trace.json` and `gate3b_bivariate_trace.json` — the two that hold every gate's diagnosis, prescription, and statistic — are **genuinely byte-identical**, confirmed by an empty `diff`. `hybrid_retrieval_trace.json` and `sandbox_trace.json` are **not**: they differ **only** in embedded wall-clock timing fields (e.g. `retrieval_time_ms: 1.931` vs `5.439`; `execution_time_ms: 2.953` vs `1.544` — real numbers from this pass), because those two files record how long the machine took, not what it decided. This is expected and correct, not a bug: timing is physically non-deterministic; the *decisions* are what the determinism claim is about. **On the poster, say "gate verdicts," not the broader "traces" or "statistical traces"** — the earlier phrasing was true under a careful reading but invites exactly the failure mode this box exists to prevent: an examiner diffs all four files, finds two differ, and calls the claim false. **If demonstrating this live or in a slide screenshot, diff only `gate2_classification_trace.json` and `gate3b_bivariate_trace.json` explicitly by name** — never `diff -r traces/` or a folder-level compare, which will show two real (and harmless) differences.
